`otf.to` drives to a spot from wherever the robot is. It plans a short path when the command starts, then follows
it like any other path.

<Scene name="driveToPose" caption="otf.to from three starting places on an open floor. Each plan is made when the command starts. Real follower, simulated drivetrain." />

## Drive to a pose

```java
// Meters, and the heading to arrive at. Write it for the blue alliance: it is flipped on red.
Command toSpot = otf.to(drive, new Pose2d(5.2, 1.4, Rotation2d.PI));
```

## Drive to a named point

A **named point** is a spot you marked in the editor's **Points** tab.

```java
// The heading is the one to arrive at, in the blue frame
Command toDepot = otf.toPoint(drive, Points.DEPOT, Rotation2d.PI);
```

## Drive to a goal known later

```java
// Read when the command starts and at each re-plan. Real field frame: not flipped on red.
Command toTarget = otf.toTarget(drive, () -> vision.scoringPose());
```

| Method | Goal is written in | Flipped on red |
| --- | --- | --- |
| `otf.to(drive, pose)` | The blue frame | Yes |
| `otf.toPoint(drive, Points.X, heading)` | The blue frame | Yes |
| `otf.toTarget(drive, supplier)` | The real field frame | No |

## Set what finished means

```java
// The default is 2 cm and 1°. Loosen it for a spot that does not need to be exact.
Command toSpot = otf.to(drive, goal)
    .withTolerance(0.05, Rotation2d.fromDegrees(2));
```

`setTolerance(meters, heading)` does the same on a command you already hold, and returns nothing.

## Set how hard it drives

An on-the-fly path takes its limits from two keys in `robot.json`.

| Key | Default | Meaning |
| --- | --- | --- |
| `onTheFlyMaxMetersPerSecond` | 4 | Top speed, m/s |
| `onTheFlyMaxMetersPerSecondSquared` | 6 | One limit for speeding up and for slowing down, m/s² |

:::note
If a drive-to-pose overshoots or arrives off target, lower the acceleration before touching anything in
[Tuning](/guides/tuning/).
:::

## Good to know

- **It works from any distance**, including already on the goal.
- **It finishes** inside the tolerance, slower than 5 cm/s, held for 0.1 s. Then it sends zero.
- **With a `field.json`** the route goes round the obstacles. Without one it is a straight run. See
  [Pathfinding](/guides/pathfinding/).
- **A failed plan** sends zero and ends at once. The reason is in `/Telemetry/Path/<name>/PlanFailure`, and
  `PlanOk` is false.
- **An unknown point name** throws `NoSuchElementException` listing the points that exist.

:::caution
Put a timeout on any drive in an autonomous, so a goal that is never reached cannot hold up the routine.
:::
