One path can hand over to the next in two ways. With a **stop**, the first ends at rest. With a **rolling end**,
the first ends still moving and the second picks up at that speed.

<Scene name="chain" caption="The same two paths, handed over two ways: settling at the hand-over, or passing through at 2 m/s. Each path is simulated on its own and the runs are joined." />

## Chain with a stop

```java
// Each path settles at its end before the next starts
Command auto = otf.follow(drive, Paths.TO_REEF)
    .andThen(otf.follow(drive, Paths.TO_SOURCE))
    .named("Reef Then Source");
```

## Chain without slowing down

In the editor, set the first path's end speed above zero. Set the second path's start speed to the same value,
and start it where the first one ends, heading the same way.

```java
FollowPathCommand first = otf.follow(drive, Paths.ROLL_A);

// continuingFrom starts the second path from exactly what the first was commanding
FollowPathCommand second = otf.follow(drive, Paths.ROLL_B).continuingFrom(first);

Command auto = first.andThen(second).named("Roll A Then B");
```

| | A path that stops | A path that ends moving |
| --- | --- | --- |
| Finishes | Settled inside the tolerance | As the robot passes the end |
| Sends zero at the end | Yes | No. The last velocity is left for the next command. |
| The next path starts from | The measured velocity | The last path's final command, through `continuingFrom` |

:::caution
A path that ends moving does not stop the robot. End every chain with a path that stops.
:::

## Chain from wherever the robot is

```java
// Plans a route to the path's start, arrives at the path's start speed, then runs the path
Command auto = otf.thenFollow(drive, Paths.TO_REEF);
```

See [Pathfinding](/guides/pathfinding/).

## Good to know

- **A stop costs time.** In the CTRE simulator, two stop-and-go moves in a row lost about a quarter of a second
  at the corner between them.
- **Do not split a path where the robot should not stop.** Draw it as one path, or use a rolling end.
- **Without `continuingFrom`** the second path starts from the measured velocity, which lags the command, and the
  first loop asks for a jump.
- **`thenFollow` matches the path.** A path that starts at rest gets a stop at its start. A path that starts
  moving gets a rolling hand-over.
