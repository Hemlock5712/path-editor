`otf.follow` makes a command that follows a path you drew in the editor.

<Scene name="follow" caption="The line is the plan, colored by planned speed. The thin trail is where the robot went. Real follower, simulated drivetrain." />

## Follow a path

```java
import static frc.robot.PathEditorNames.*;

// otf is the Pathfinding object you built in robot init
Command toReef = otf.follow(drive, Paths.TO_REEF);
```

That is the whole thing. The command requires the drivetrain, runs the path's events, flips for red, and stops
the robot at the end.

:::note
You need `otf` first. [The first path](/start/first-path/) builds it.
:::

## Use it in an autonomous

```java
@Autonomous(name = "To Reef")
public class ToReefAuto extends PeriodicOpMode {
  private final Command routine;

  public ToReefAuto(Robot robot) {
    // Build the command once, here. Never when autonomous starts.
    routine = robot.drive.otf.follow(robot.drive, Paths.TO_REEF);
  }

  @Override
  public void start() {
    Scheduler.getDefault().schedule(routine);
  }

  @Override
  public void end() {
    Scheduler.getDefault().cancel(routine);
  }
}
```

## Change one path's settings

Build the follower yourself when one path needs settings the others do not.

```java
// A looser finish for a path that only has to get close
FollowerConfig loose = FollowerConfig.defaults(paths.robot()).toBuilder()
    .positionToleranceMeters(0.05)
    .headingToleranceRadians(Math.toRadians(3))
    .build();

Command go = new FollowPathCommand(
        Paths.TO_REEF,                                    // names the command and its telemetry
        drive,                                            // the drivetrain it requires
        new PathFollower(paths.get(Paths.TO_REEF), loose),
        () -> drive.getPose(),                            // where the robot is
        () -> drive.getFieldVelocity(),                   // how fast, field-relative
        velocity -> drive.driveFieldVelocity(velocity),   // how to drive
        FieldFrame.RED_HALF_TURN)                         // the flip on red
    .withEvents(paths);                                   // a hand-built command needs this for events
```

## Options

Each returns the command, so they chain.

| Method | What it does |
| --- | --- |
| `onEvent(Events.X, command)` | Runs a command at an event, for this path only. See [Events](/guides/events/). |
| `withMovingGoal(supplier)` | The end follows a goal from a camera. See [Moving goals](/guides/moving-goals/). |
| `finishWhen(condition)` | Holds the end until the condition is true. |
| `continuingFrom(previous)` | Picks up the last path's speed. See [Chaining paths](/guides/chaining-paths/). |
| `withWheelForces(robot, modules, drive)` | Sends each wheel's push. See [Wheel forces](/guides/wheel-forces/). |
| `withFrame(supplier)` | Replaces the alliance lookup. See [Alliances](/guides/alliances/). |

:::caution
Keep what a `with...` method returns. WPILib's compiler check refuses a command that is returned and thrown
away.
:::

## Good to know

- **It finishes** within 2 cm and 1° of the end, slower than 5 cm/s, held for 0.1 s.
- **The robot can start off the path.** The follower steers onto it. From far away, use `otf.thenFollow`, which
  plans a route to the start first. See [Pathfinding](/guides/pathfinding/).
- **A wrong name fails in robot init**, with a message that lists the paths that exist.
- **Reuse the command.** Each start resets it.
