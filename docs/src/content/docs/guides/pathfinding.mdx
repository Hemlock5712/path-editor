With a `field.json` in `deploy/paths`, every on-the-fly command routes round the field's obstacles. Nothing
changes in the call.

<Scene name="pathfind" caption="otf.to with a field file loaded, on the 2026 field. The planner grows the obstacles, finds the shortest route, smooths it and drives it. Real follower, simulated drivetrain." />

## Give the library a field

Mark the obstacles on the editor's **Settings** page, under Field, and save. The default is the 2026 field: both
hubs, both towers and the four trench supports.

`PathLibrary.loadAll()` reads it at boot, and a damaged file stops the robot there with a message that names it.
`paths.hasFieldFile()` tells you whether one was found.

:::caution
Each obstacle is grown by `bumperLengthMeters` and `bumperWidthMeters` from `robot.json`. If those are missing
or wrong, the clearance is wrong. Measure the bumpers.
:::

## Pick a command

All four return a `PathfindCommand`. [Drive to a pose](/guides/drive-to-pose/) covers the first three.

| Command | Goes to |
| --- | --- |
| `otf.to(drive, pose)` | A pose written for blue |
| `otf.toPoint(drive, Points.X, heading)` | A named point from the editor |
| `otf.toTarget(drive, supplier)` | A pose in the real field frame, read at start |
| `otf.thenFollow(drive, Paths.X)` | The start of a drawn path, then the path |

## Pathfind into a drawn path

```java
// Plans to the path's first waypoint, arriving along its start direction at its start speed.
// Then the path runs, with its events.
Command score = otf.thenFollow(drive, Paths.TO_REEF);
```

A path that starts at rest gets a stop at the hand-over. A path that starts moving gets a rolling one.

## Change when it re-plans

| Trigger | Default | Change it with |
| --- | --- | --- |
| The robot is knocked further than this off the path | 0.2 m | `replanAbove(meters)` |
| You ask | | `replan()` |

```java
// Re-plan when the robot is more than 0.3 m off the path.
// replanAbove(Double.POSITIVE_INFINITY) turns this off, so it only re-plans when asked.
PathfindCommand toSpot = otf.to(drive, goal).replanAbove(0.3);
```

A re-plan starts from where the robot is and the speed it is going, at most once every half second.

## Allow for a mechanism that sticks out

A **footprint** is a named outline: the bumpers plus how far a mechanism reaches on each side. Define them in
`robot.json`.

```java
// Read once, when a command starts. On otf it applies to every command built afterward.
otf.withFootprint(() -> intake.isOut() ? "intakeOut" : "bumpers");
```

`"bumpers"` is always available, and `paths.footprintNames()` lists the rest. An unknown name throws
`NoSuchElementException`.

## Check the plan

Each plan publishes under `/Telemetry/Path/<name>/`.

| Entry | Meaning |
| --- | --- |
| `PlanOk` | Whether a route was found |
| `PlanFailure` | Why not, or empty |
| `PlanMicros` | How long planning took, microseconds |
| `Replans` | How many times this run has planned again |
| `StartSnap`, `GoalSnap` | Meters an end was moved out of an obstacle |
| `MinClearance` | Meters from the bumpers to the nearest obstacle or wall along the plan |
| `PlanClear` | Whether the outline keeps the margin along the whole plan |
| `Plan` | The planned path, published again at every re-plan |

## Good to know

- **A start or goal inside an obstacle is snapped** to the nearest free point for routing. The path still starts
  at the robot and ends at the goal.
- **It does not see other robots.** The field is the static map in `field.json`.
- **It cannot prevent a push into an obstacle.** It re-plans from where the robot ends up.
- **Concave obstacles are filled in.** That is safe, but can close a pocket the robot would fit in.
- **Following a drawn path does not use footprints.** The editor checked the outline when you drew it.
