A drawn path starts where you drew it. During a match the robot is rarely there. The **pathfinder** is the piece that plans a path from wherever the robot is to a goal, around the obstacles in `field.json`, in a few milliseconds. The result is an ordinary path, followed by the same follower as a path drawn in the editor.

Robot code does not call it directly. `PathLibrary` builds it at boot and `Pathfinding` makes the commands that use it. See [Pathfinding](/guides/pathfinding/) for the robot code and [On-the-fly paths](/concepts/on-the-fly/) for what happens around each plan.

## The idea in plain words

A robot is a rectangle, and checking a rectangle against every obstacle at every heading is slow. So the pathfinder makes the problem simpler. It makes every obstacle fatter by the robot's size, then treats the robot as a single point. If the point stays out of the fat obstacles, the real robot stays off the real ones.

Once the robot is a point, the shortest way around a set of polygons is always a chain of straight lines from corner to corner. The pathfinder works out which corners can see each other once, at boot. At go it only has to pick the shortest chain.

## At boot

This happens once, when `PathLibrary.loadAll()` runs in robot init.

### 1. Grow the obstacles

Each obstacle is grown by the **reach** of the robot plus a **margin**. The reach is the bumpers' half-diagonal: the distance from the robot's center to a bumper corner.

```text
reach = sqrt(length^2 + width^2) / 2
grow  = reach + margin

0.85 m square bumpers:  reach = 0.601 m
margin 0.05 m:          grow  = 0.651 m
```

No part of the robot is further from its center than the reach, whichever way it is turned. That is why growing by the half-diagonal is safe at any heading: the planner does not need to know the heading to know the center is far enough away.

Growing a shape by a distance rounds its corners. The pathfinder draws each rounded corner as short straight pieces, each turning at most 30 degrees, and places the points slightly outside the true arc so the grown shape always contains the exact one. For the default robot the grown shape is at most 2.3 cm larger than the exact one.

### 2. Move the walls in

The field's walls move in by the same grow distance. The robot's center has to stay inside this smaller rectangle.

### 3. Build the visibility graph

Every corner of every grown shape that is in free space becomes a node. Two nodes are joined when the straight line between them does not pass through the inside of any grown shape. Touching a corner or running along an edge is allowed. This set of nodes and lines is the **visibility graph**. On the bench's six-obstacle test field it has 83 nodes.

## At go

`Pathfinder.plan` takes the robot's pose, its field velocity and the goal pose.

### 1. Snap the start and the goal

A start or goal inside a grown obstacle, or too close to a wall, has no route by the rules above. The pathfinder moves it to the nearest free point and plans from there. The path still starts at the robot and ends at the real goal, passing through the snapped points, and the result reports how far each one was moved.

### 2. Find the shortest route

If the start can see the goal, the route is one straight line. Otherwise the start and the goal are joined to every node they can see, and **A\*** searches the graph. A\* is a shortest-path search that tries the most promising node first, judged by the distance traveled so far plus the straight-line distance still to go. Ties go to the lowest node number, so the same inputs always give the same route.

### 3. Turn the route into waypoints

The route's corners become the waypoints of the same quintic spline a drawn path uses. See [The curve](/concepts/the-curve/). If the robot is moving faster than 0.1 m/s, the first waypoint's direction is the direction it is already traveling, so the path leaves along the robot's motion. The other directions are chosen automatically. The heading turns from the robot's current heading to the goal's heading along the way.

### 4. Sweep the bumpers and refit

A spline through corner points cuts inside them a little, so the smooth path can come closer to an obstacle than the corner-to-corner route did. The pathfinder checks. It places the real bumper rectangle on the path every 2 cm, at the heading planned for that spot, and measures the gap to every obstacle and wall.

Each stretch closer than the margin gets a new waypoint: the point of the straight route under the stretch's worst spot. The spline is fitted again through the longer list and swept again, up to 8 times. Because the straight route itself keeps the margin, pulling the spline toward it fixes the problem. Stretches next to a snapped start or goal are not checked, since they begin inside the margin.

### 5. Build the speed plan

The finished spline goes through the same [speed plan](/concepts/speed-plan/) as a drawn path. It starts at the robot's current speed, ends at rest, and is capped at 4 m/s and 6 m/s² unless the robot file says otherwise. The robot's own traction and motor limits still apply.

## The numbers

| Number | Default | Where it lives |
| --- | --- | --- |
| Margin | 0.05 m | `PlannerConfig.marginMeters` |
| Corner arc step | 30 degrees | `PlannerConfig.arcStepRadians` |
| Sweep spacing | 0.02 m | `PlannerConfig.checkStepMeters` |
| Refits allowed | 8 | `PlannerConfig.maxRefits` |
| Speed cap | 4 m/s | `PlannerConfig.maxMetersPerSecond` |
| Acceleration cap | 6 m/s² | `PlannerConfig.maxMetersPerSecondSquared` |
| Moving-start threshold | 0.1 m/s | fixed in `Pathfinder` |
| Hand-over approach | 0.5 m | `Pathfinder.APPROACH_METERS` |

A gap between two obstacles has a route through it only when it is wider than twice the grow distance: 1.30 m for the default robot at the 0.05 m margin.

## Timings

These were measured on a desktop PC with other work running, not on a roboRIO or a Systemcore. The robot controller has not been measured.

| What | Time |
| --- | --- |
| One plan, warmed up, 9.2 m route through six obstacles | 1.9 to 2.3 ms median, 4.8 to 8.1 ms at the 95th percentile |
| The same plan by part | search 0.08 ms, smoothing and sweep 1.7 ms, speed plan 0.15 ms |
| Plans on the three other bench routes | 0.47 to 1.0 ms median |
| First plan in a fresh JVM | 17 to 35 ms |
| Boot, growing and graph | 32 to 135 ms |

The first plan is slow because Java has not compiled the code yet. `PathLibrary` removes that cost from the match by making 40 throwaway plans at boot on each of the two bumper pathfinders, the 0.05 m one and the 0.15 m one described in [On-the-fly paths](/concepts/on-the-fly/).

## How it is tested

The library's `PathfinderTest` checks:

- route lengths against a separate geometric calculation, on 60 random single-obstacle cases;
- 300 random start and goal pairs whose routes never enter a grown obstacle;
- 300 random pairs, with random headings and a third of them starting in motion, whose swept bumpers keep the margin on the finished path. In that run 34 needed refits, none failed, and the closest was 5.1 cm;
- that the same inputs give the same path, plus snapping, a moving start, the end heading and bad field files.

These are simulator and bench results. The library has not run on a real robot.

## What it does not do

- **Moving obstacles.** The field is fixed. Another robot in the way is not seen. A goal that moves is supported, see [Moving goals](/concepts/moving-goals/).
- **Concave shapes.** Each obstacle is replaced by its **convex hull**, the shape a rubber band makes when stretched around it. An L-shaped obstacle is planned around as if its notch were filled in.
- **Tight squeezes by turning.** Growing by the half-diagonal closes gaps that a long robot could pass through nose first. Only a robot with a named [footprint](/concepts/footprints/) gets a second try at those.
- **Tuning the curve.** Smoothing only adds waypoints. It does not adjust how strongly the spline bends at each one.

:::caution
`PlanResult.clear()` is false when 8 refits were not enough and the bumpers still come inside the margin somewhere. The plan is returned anyway. Check `clear()` if you call the pathfinder yourself.
:::
