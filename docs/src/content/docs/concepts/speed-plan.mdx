The **speed plan** says how fast the robot may drive at every distance `s` along the path: the fastest speed that
breaks none of its limits. [VelocityProfile](/reference/core/velocityprofile/) computes it once, at boot.

<Scene name="limits" caption="The speed plan for one path at three acceleration limits. The line is colored by planned speed, and the chart shows planned speed against the speed the robot reached. Real follower, simulated drivetrain." />

## What it does

1. **Make a grid** of points spaced evenly along the path. Inside one cell the acceleration is constant.

   ```text
   v1² = v0² + 2 * a * ds          speed at the far end of a cell
   t   = 2 * ds / (v0 + v1)        time to cross the cell
   ```

2. **Set a speed ceiling** at each grid point, from the limits below. A [cusp](/concepts/the-curve/), where the
   path doubles back, gets its own grid point with a ceiling of zero.
3. **Forward pass.** From the start speed, it asks how fast the robot can be going by here if it speeds up as
   hard as the limits allow.
4. **Backward pass.** From the end speed, it asks how fast the robot may be going here and still slow down for
   everything ahead.
5. **The plan** is the lower of the two answers at every point.

Each step keeps the limits at both ends of its cell, with two rounds of a fixed-point iteration and a bisection
where they disagree.

## The limits

**Traction.** Everything that pushes on the floor shares one limit `A`. See [Traction](/concepts/traction/).

```text
√(a² + (v²κ)²) + c * |α| ≤ A
```

`a` is the acceleration along the path, `v²κ` the sideways acceleration, `α` the spin acceleration, and
`c = I / (m * r)` from the moment of inertia `I`, mass `m` and module radius `r`. With `a` at zero this gives the
fastest steady speed through a bend. `θ''` is the second derivative of the heading along the path.

```text
v ≤ √(A / (|κ| + c * |θ''|))
```

**Motors.** When speeding up, the push along the path is capped by what the drive motors can give at the fastest
wheel's speed. When braking, only the stator current limit applies.

**Wheel speed.** No wheel may roll faster than the wheel-speed cap. The fastest wheel moves at between 1 and
`1 + r * |θ'|` times the robot's speed, so planned spin takes speed away from translation.

**Caps.**

| Cap | Where it is set | Effect |
| --- | --- | --- |
| Path speed | `maxMetersPerSecond` in the path file | Speed ceiling everywhere |
| Path acceleration | `maxMetersPerSecondSquared` in the path file | Limit on speeding up and on braking |
| Zone speed and acceleration | `constraintZones` in the path file | The same two caps over a stretch |
| Spin rate | `maxAngularRadPerSec` in robot.json | `v * \|θ'\| ≤ ω_max` |
| Spin acceleration | `maxAngularRadPerSecSquared` in robot.json | `\|a * θ' + v² * θ''\| ≤ tractionShare * α_max` |
| Start and end speed | `startMetersPerSecond`, `endMetersPerSecond` in the path file | Where each pass starts |

- **A [ConstraintZone](/reference/core/constraintzone/)** caps every grid point of every cell it touches. The
  backward pass brakes for it, so the robot is already at the zone's speed when it reaches the zone's start.
- **An end speed above zero is a rolling end.** See [Chaining paths](/guides/chaining-paths/).

## Short hops and turns on the spot

The heading is tied to distance, so a big turn over a short hop slows the translation to give the spin time. A
path whose two waypoints are at the same place is a **turn on the spot**. It is planned on a 1 mm segment that
ends exactly on the point.

Planned times with a spin cap of 540 degrees per second and a spin acceleration cap of 720 degrees per second
squared. The floor is the time a minimum-jerk turn needs under the same caps.

| Hop | Planned time | Floor |
| --- | --- | --- |
| 0.2 m with an 80 degree turn | 0.84 s | 0.80 s |
| 0.05 m with a 180 degree turn | 1.27 s | 1.20 s |
| 0 m with a 90 degree turn | 0.90 s | 0.85 s |

## The numbers

| Name | Value | Unit | What it is |
| --- | --- | --- | --- |
| Grid spacing | 3 | cm | The default. The path is split into equal cells, so the real spacing is slightly smaller. |
| Minimum cells | 16 | | Every path gets at least this many, however short |
| Grid points, 16 m example path | 547 | | In the library's tests |
| Grid accuracy | 0.1 to 0.9 | % | Total time on a 3 cm grid against a 1 mm grid, on the test paths |
| `A`, default robot | 12.8 | m/s² | The traction limit |
| Bend of radius 1 m, no turning | about 3.6 | m/s | The traction speed ceiling with the default robot |
| Wheel-speed cap, default robot | 4.56 | m/s | The motor's free speed at the wheel, unless `maxWheelMetersPerSecond` is set in robot.json |
| Traction between grid points | within 2 | % | Exact at every grid point, checked by the library's tests |
| Turn on the spot segment | 1 | mm | The robot moves at most this far |
| Build time, 16 m example path | about 0.2 | ms | Desktop PC, warm JVM. 23 to 65 ms for the first path in a fresh JVM. |

## What it does not do

- **It does not react to the real robot.** It is computed once. [The follower](/concepts/the-follower/) deals
  with what actually happens.
- **It does not know the floor.** If the carpet has less grip than robot.json says, the plan asks for too much.
- **It has not been checked on a real robot.** The numbers here come from the library's tests and a simulator.
