Ask a robot to push on the floor too hard and the wheels slip, or the robot starts to tip. Myelin works out one
number for how hard it may push, the **traction limit**, and holds every plan to it.

<TractionBars />

## What it does

[RobotConfig](/reference/core/robotconfig/) reads [robot.json](/files/robot-file/) at boot.

1. **Grip.** `μ * g` is the most acceleration the tread can hold before it slides. `μ` is the friction
   coefficient and `g` is gravity, 9.81 m/s².
2. **Tipping.** `g * x / h` is the acceleration that would lift the wheels on one side. `h` is the height of the
   center of mass. `x` is the **tip distance**, from the center to the nearest tipping edge.
3. **Take the smaller**, then keep a margin with `tractionShare`. The default of 0.9 leaves 10 % unused.

   ```text
   A = tractionShare * min(μ * g, g * x / h)
   ```

   `A` is the traction limit in m/s², for all directions combined.
4. **Share it.** Speeding up, cornering and spinning draw on the one budget. The
   [speed plan](/concepts/speed-plan/) solves this for the largest `a` at every point.

   ```text
   √(a² + (v²κ)²) + c * |α| ≤ A
   ```

   | Term | What it is |
   | --- | --- |
   | `a` | Speeding up or braking along the path, m/s² |
   | `v²κ` | Cornering: the sideways acceleration at speed `v` on a bend of curvature `κ` |
   | `c * \|α\|` | Spinning: the extra push each wheel needs for a spin acceleration `α` |

   `c` is a length, `I / (m * r)`: the moment of inertia over the mass times the module radius.
5. **Check the motors.** [Motor](/reference/core/motor/) models a brushless motor as a straight line from stall
   torque at zero speed to zero torque at free speed.

   ```text
   current = (12 V - back-EMF at this speed) / winding resistance
   current = clamp(current, 0, statorCurrentLimitAmps)
   accel   = motors * torque per amp * gear ratio / wheel radius * current / mass
   ```

   When braking, only the stator limit applies, and the traction limit is what binds.
6. **Plan under it, command a little over.** The planner uses `A`. The follower's
   [output limiter](/concepts/output-limiter/) allows `A / tractionShare`, so feedback has the margin to correct
   errors with. Spin is split the same way when `maxAngularRadPerSecSquared` is set.

## The numbers

| Quantity | robot.json key | Default |
| --- | --- | --- |
| Friction coefficient `μ` | `frictionCoefficient` | 1.5 |
| Center of mass height `h` | `centerOfMassHeightMeters` | 0.2 m |
| Tip distance `x` | `tipDistanceMeters` | `moduleRadiusMeters / √2`, which is 0.29 m |
| Share | `tractionShare` | 0.9 |

```text
grip     = 1.5 * 9.81         = 14.7 m/s²
tipping  = 9.81 * 0.29 / 0.2  = 14.2 m/s²
A        = 0.9 * 14.2         = 12.8 m/s²
```

| Name | Value | Unit | What it is |
| --- | --- | --- | --- |
| `A`, defaults | 12.8 | m/s² | Tipping sets it. `RobotConfig.tractionLimit()` reports which term does. |
| `A`, modules at 0.254 m on each axis | 11.2 | m/s² | The limit with the modules moved in |
| `A / tractionShare`, defaults | 14.2 | m/s² | The follower's limit |
| `c`, defaults | about 0.24 | m | `RobotConfig.spinLeverMeters()` |
| Default motor | Kraken X60 with FOC | | 12 V, 9.362 N·m stall torque, 476.1 A stall current, 5,785 rpm free speed |
| Stator limit | 120 | A | Binds at low speed, where the motors can push for 20.9 m/s² |
| Motors become the limit | about 3.9 | m/s | Wheel speed above which they cannot supply 12.8 m/s² |
| Free speed at the wheel | 4.56 | m/s | The motors can add nothing more |
| `μ` where grip takes over | 1.45 | | `x / h` with the default geometry |

- **`centerOfMassHeightMeters` of 0** turns the tipping term off.
- **`tipDistanceMeters`** is one value for every direction: the smaller of the modules' x and y distances from
  the center. Leave it out for a square base.

:::caution
The default center of mass height is a guess. Measure yours, because with the defaults it is the number that sets
the limit.
:::

## If the robot slips

The library has no slip detection. Change robot.json:

1. Lower `tractionShare`. This always lowers the limit.
2. Lower `frictionCoefficient` to the floor's real value. With the default geometry, a small reduction from 1.5
   changes nothing, because tipping sets the limit until `μ` falls below 1.45.

Both apply to every path at the next boot, and to the teleop limiter if you use
[DriveLimiter](/guides/teleop-limiter/).

In simulation, a floor with a real `μ` of 0.91 under a plan made for 1.5 left wheel odometry 31 cm off at the end
of a run, and 10.6 cm off once robot.json had the real `μ`.

:::note
The defaults are in the source and are not a measurement of your robot. The library has not run on a real robot.
:::

## What it does not do

- **It does not measure the floor.** `μ` is whatever robot.json says.
- **It does not model each wheel's load.** That is the [wheel force feed-forward](/concepts/feed-forward/).
- **It does not change during a match.**
