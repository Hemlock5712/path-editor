An **on-the-fly path** does not exist until the command starts. The library plans it from where the robot is,
around the field's obstacles, and plans again if the robot is knocked off it or the goal moves.

<Scene name="pathfind" caption="Plan, then follow. Each route was planned from the start pose when the scene began. Real follower, simulated drivetrain." />

## What it does

1. **Plan.** `OnTheFly.start` takes the measured pose and velocity and asks the
   [pathfinder](/concepts/pathfinder/) for a path to the goal. With no route it returns false, and the command
   sends a stop.
2. **Pick a margin.** It compares the shortest route on the wide pathfinder and on the main one.

   ```text
   use the wide plan when:  wide route length <= 1.15 x main route length
   ```

3. **Check it is clear.** If the chosen plan is not clear, the other pathfinder is tried, and a clear plan wins
   even when it is longer. With neither clear, one is driven anyway and `PlanResult.clear()` reports it.
4. **Follow.** A new `PathFollower` starts on the path. Every loop, `OnTheFly.step` runs one
   [follower](/concepts/the-follower/) step and returns the field speeds to drive.
5. **Re-plan.** When a trigger fires, it plans a whole new path from the robot's current pose and velocity and
   starts a new follower on it.

## What triggers a re-plan

| Trigger | Condition | At most once per |
| --- | --- | --- |
| Off the path | more than 0.20 m to the side of the path | 0.5 s |
| The goal moved | more than 0.10 m from the goal the path was planned to | 0.2 s |
| Asked | `requestReplan()` was called | no limit |

The first two only fire while the follower is tracking the path. Smaller goal movements are handled by the
follower itself. See [Moving goals](/concepts/moving-goals/).

## Hand over into a drawn path

`otf.thenFollow(drive, Paths.TO_REEF)` plans to the start of a drawn path, then follows it.

1. The on-the-fly path arrives traveling along the drawn path's start direction, at its start speed.
2. The route ends with a straight approach along that direction.

   ```text
   approach length = 0.5 m + (end speed)^2 / (2 x max acceleration)
   ```

3. The approach is used only when it is free of obstacles and the goal is more than twice its length away.
   Otherwise the robot arrives however the route brings it.

A drawn path that starts moving gets a rolling hand-over. One that starts at rest gets a normal stop.

## Which frame a goal is in

`OnTheFly` works in the real field frame. The commands convert a goal first, with the alliance read at start.

| Goal | Given in | On the red alliance |
| --- | --- | --- |
| `otf.to(drive, pose)` | the blue frame, as authored | flipped |
| `otf.toPoint(drive, Points.X, heading)` | the blue frame, as authored | flipped |
| `otf.thenFollow(drive, Paths.X)` | the drawn path's start | flipped |
| `otf.toTarget(drive, supplier)` | the real field frame | used as given |
| `withMovingGoal(supplier)` | the real field frame | used as given |

:::caution
A pose from a camera is already in the real frame. Give it to `toTarget` or `withMovingGoal`. Giving it to `to`
flips it on red and sends the robot to the wrong end of the field.
:::

## The numbers

| Name | Value | Unit | What it is |
| --- | --- | --- | --- |
| Wide margin | 0.15 | m | Tried first, where the field has room |
| Main margin | 0.05 | m | Used where the wide one has no route or a long detour |
| Wide route limit | 1.15 | times the main route | Longer than this and the main plan is used |
| `OnTheFly.DEFAULT_REPLAN_METERS` | 0.20 | m | Off-path threshold. A command changes it with `replanAbove`. |
| Goal-moved threshold | 0.10 | m | Plans the whole path again |
| `onTheFlyMaxMetersPerSecond` | 4 | m/s | Speed cap, a key in `robot.json` |
| `onTheFlyMaxMetersPerSecondSquared` | 6 | m/s² | Cap for speeding up and slowing down, a key in `robot.json` |
| Approach length | 0.5 | m | Plus the braking distance from the end speed |
| Route search | about 0.1 | ms | Comparing the two routes, on a desktop PC |
| Plan time | about 1, under 5 at the 95th percentile | ms | On a desktop PC, not a roboRIO or a Systemcore |

- The robot's own traction and motor limits still apply, so a cap above what the robot can do changes nothing.
- `OnTheFly.maxPlanMicros()` reports the slowest plan of a run. See [Telemetry](/guides/telemetry/).
- In simulation on six test fields, with 240 starts and goals, adding the wide margin took the runs that touched
  an obstacle from 8 to 3 without losing a route.

:::note
None of this has run on a real robot. The end-to-end suite ran 119 of 119 simulated runs, on blue and red,
without contact.
:::

## What it does not do

- **It does not see other robots**, or anything else that is not in `field.json`.
- **It does not patch a path.** Every re-plan is a whole new plan.
- **It does not prevent a push into an obstacle.**
- **It needs a field file.** Without one, every plan is a straight drive to the goal. See the
  [field file](/files/field-file/).
