A drawn path ends at a fixed spot, but a game piece rolls and a scoring peg is a few centimeters off the map. A
**moving goal** binds the end of the path to a supplier, and the follower bends the rest of the path to the
latest value.

<Scene name="tag" caption="A path whose end is bound to a goal that appears partway through the run. The rest of the path is planned again to it. Real follower, simulated drivetrain." />

## What it does

1. Each step the follower calls the supplier once. It is a `Supplier<Optional<Pose>>`, in the same frame as the
   robot's measured pose.
2. An empty value holds the last goal. Until the first estimate, the goal is the end of the path as drawn.
3. When the goal has moved more than 2 cm or 2° from the current one, the follower plans the rest of the path
   again. The new piece is one quintic curve, two waypoints, from where the robot is on the path to the new goal.
4. The join matches the old path in position, direction and curvature. Heading blends to the goal's heading.
5. Speed runs from the planned speed at the join to the path's own end speed, under the path's own maximums.
6. The approach direction is the old final direction, turned by the angle the goal's heading changed. If that
   would approach from past the goal, the piece heads straight in.
7. Unfired events keep their place in proportion. An event 40 % of the way through the distance left is 40 % of
   the way along the new piece.
8. Within 0.45 m of the goal nothing is re-planned. The [stopping law](/concepts/stopping-law/) drives straight
   at the latest value.

## Average a noisy goal

A raw camera estimate jitters by a centimeter or two each frame. The second form of `bindGoal` averages the
estimates first.

```java
follower.bindGoal(() -> vision.pieceIfSeen(), 0.5);   // smoothing time, seconds
```

1. Each estimate moves the average a fraction `k` of the way toward itself.

   ```text
   k = max( 1/n ,  1 − e^(−dt / T) )
   average = average + k · (estimate − average)
   ```

   `n` is the number of estimates so far, `dt` the loop time and `T` the smoothing time in seconds.
2. At first `1/n` wins, and the result is the plain mean. Later it is a running average over about `T` seconds.
3. An estimate more than 25 cm or 20° from the average is suspect. One or two in a row are ignored.
4. The third in a row restarts the average from that estimate, with `n` back to 1. Any estimate that agrees
   resets the count.
5. The heading is averaged the same way, the short way round.

| Use | When |
| --- | --- |
| `bindGoal(goal)` | The supplier already filters its estimates. [`TagGoal`](/reference/wpilib/taggoal/) does. |
| `bindGoal(goal)` | The goal is held in the odometry frame and moves with the robot's own pose corrections |
| `bindGoal(goal, seconds)` | The estimates arrive raw from a camera, for a goal that stands still or creeps |

:::caution
Do not average a goal that is already filtered. The two filters stack, and the goal lags.
:::

In simulation with 2 cm of noise, a raw goal never settled, and the averaged goal settled as soon as a goal with
no noise.

## Hold the finish

```java
// Drive to the goal and hold it. Finish only once the cameras have a lock.
follower.bindGoal(() -> vision.scoringPoseIfSeen())
    .finishWhen(() -> vision.hasLock());
```

- **Give the command a timeout.** If the condition never becomes true, the path never finishes.
- **A path with a rolling end ignores `finishWhen`.**

## The numbers

| Name | Value | Unit | What it is |
| --- | --- | --- | --- |
| Re-plan threshold | 2 cm or 2° | | How far the goal must move to plan the tail again |
| No re-plan radius | 0.45 | m | The 0.3 m finish radius plus a 0.15 m minimum for the new piece |
| Threshold in the finish | none | | The goal follows every estimate |
| Smoothing time `T` | 0.5 | s | The starting value the library's javadoc suggests |
| Changeover | about 25 | estimates | With a 0.02 s loop and `T` of 0.5 s |
| Stray estimate | 25 cm or 20° | | Distance from the average that makes an estimate suspect |
| Strays to restart | 3 | in a row | The average starts again |
| On-the-fly re-plan | 10 | cm | Goal movement that makes [`OnTheFly`](/reference/plan/onthefly/) plan around obstacles |

## What it does not do

- **The new piece knows no obstacles.** For a large move, [on-the-fly paths](/concepts/on-the-fly/) plan again
  around them. A drawn path has no pathfinder, so draw its last stretch clear of obstacles.
- **No zones.** Constraint zones and face-point zones are not carried into the new piece.
- **No turn on the spot** once its goal moves and the tail is re-planned.
- **No odometry-frame latch.** The supplier does that, as [the tag filter](/concepts/tag-filter/) does.

:::note
The library has not run on a real robot. These thresholds are defaults from the simulator.
:::
