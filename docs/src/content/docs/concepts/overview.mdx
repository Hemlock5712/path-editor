This section explains how the library works inside. You need it when a path does something you did not expect,
or when you want to read the source.

<Pipeline />

## 1. Plan

Planning happens once, in robot init. `Path.build` turns one path file into a `Path` object.

1. **The curve.** The waypoints are joined by smooth pieces that meet with the same position, direction and
   **curvature**, which is how sharply the path is turning. Everything afterward is measured in meters along the
   curve, a distance called `s`. [The curve](/concepts/the-curve/)
2. **The heading.** The path carries the robot's heading at every `s`. It can hold, face the way it is going,
   turn to targets, or keep pointing at a spot on the field. [The heading](/concepts/heading/)
3. **The speed.** For every point, the planner finds the fastest speed that breaks no limit. A forward sweep asks
   how fast the robot can have got here. A backward sweep asks whether it can still slow down in time. The plan
   is the lower of the two. [The speed plan](/concepts/speed-plan/)

<SpeedPlan />

The main limit is **traction**: how hard the tires can push before they slip, or before the robot tips. Speeding
up, braking, cornering and spinning all draw on that one budget. [Traction](/concepts/traction/)

## 2. Follow

Following happens every loop. `PathFollower.step` takes the measured pose and velocity and returns the velocity
to command.

1. **Convert to blue.** On red the pose is flipped in and the answer is flipped out.
   [The field frame](/concepts/field-frame/)
2. **Find the robot on the path.** The closest point on the curve, searched near where it was last loop.
3. **Pick a law.** Along the path it tracks the plan. In the last 30 cm it drives straight at the goal. On a turn
   on the spot, it turns. [The follower](/concepts/the-follower/)
4. **Read the plan a little ahead.** A drivetrain answers a command about 50 ms late, so the follower asks for
   what the plan wants 50 ms from now.
5. **Correct.** A push back toward the line in proportion to how far off it is, and the same for the heading.
6. **Brake for the end.** The speed is capped by what the robot can still stop from.
   [The stopping law](/concepts/stopping-law/)
7. **Limit.** One limiter holds the result to what the wheels can do.
   [The output limiter](/concepts/output-limiter/)
8. **Fire events** the robot has just passed. [Path events](/concepts/path-events/)

Two extras sit on top: a push for each wheel, [Feed-forward](/concepts/feed-forward/), and an end that follows a
goal, [Moving goals](/concepts/moving-goals/).

## 3. Plan on the field

With no drawn path, the library makes one when the command starts.

1. **Grow the obstacles.** At boot, each obstacle in the field file is made larger by the robot's reach.
2. **Find the shortest route.** The corners of the grown shapes that can see each other form a graph. A search
   finds the shortest way from the robot to the goal.
3. **Smooth it.** The route's corners become waypoints of an ordinary curve. The robot's outline is swept along
   it, and where it comes too close, a waypoint is added.
4. **Plan the speed**, the same way as for a drawn path.
5. **Follow it**, with the same follower. If the robot is knocked off, it plans again from where it is.

[The pathfinder](/concepts/pathfinder/) covers the first three steps and
[On-the-fly paths](/concepts/on-the-fly/) the rest. A mechanism past the bumpers changes the outline.
[Footprints](/concepts/footprints/)

## The pieces that reuse it

| Feature | Built from | Explained in |
| --- | --- | --- |
| Driving by hand without slipping | The output limiter on its own | [The output limiter](/concepts/output-limiter/) |
| Stopping on a spot measured from a tag | A filter on the tag's sightings, feeding a moving goal | [The tag filter](/concepts/tag-filter/) |
| Holding a line while the driver drives | The stopping law in one dimension, across the line | [The rail law](/concepts/rail-law/) |
| Nudging the intake onto a piece | A choice of piece, a sideways slide, and the limiter | [The piece assist](/concepts/piece-assist/) |

## Read the source

About 1,500 lines carry the ideas. The sources jar comes with the vendordep, and every file starts with a comment
that says what it does.

1. `follow/PathFollower.java`: `step()` and its three laws.
2. `follow/StoppingLaw.java`, 28 lines of law, and `follow/OutputLimiter.java`.
3. `core/VelocityProfile.java`, for the two passes.
4. `plan/OnTheFly.java` and `plan/Pathfinder.java`.

Treat `QuinticSpline`, `PathGeometry` and `HeadingProfile` as a box. A distance along the path goes in. A point,
a direction, a curvature and a heading come out.

:::note
Every number in this section is a default in the source, or a measurement from the simulator or a desktop PC.
None is from a real robot, because the library has not run on one yet.
:::
