A plan says where the robot should be and how fast. The **follower**,
[`PathFollower`](/reference/follow/pathfollower/), takes the measured pose and velocity every loop and returns
one field-relative velocity for the drivetrain.

<Scene name="shove" caption="A hit partway along the path. The faint robot is the same run with no hit. The follower steers back onto the line, and the plan is not rebuilt. Real follower, simulated drivetrain." />

## What it does

The path and the follower are built in robot init. `start()` does no path work. Robot code then calls `step()`
once per loop until `isFinished()` is true.

1. **Frame.** The pose, the velocity and any moving goal are converted into the blue frame with the
   [`FieldFrame`](/reference/core/fieldframe/) given to `start()`. The output is converted back at the end.
2. **Moving goal.** If a goal is bound, its supplier is read. See [Moving goals](/concepts/moving-goals/).
3. **Progress.** It finds `s`, the distance along the path of the point closest to the robot, near the last `s`.
4. **Pick a law.** One of the three laws below gives the wanted velocity.
5. **Limiter.** The [output limiter](/concepts/output-limiter/) returns the closest velocity the robot can reach
   this loop without slipping.
6. **Events.** Events the robot is passing are fired. See [Path events](/concepts/path-events/).
7. **Finished.** It checks whether the path is done.

## The three laws

| Law | When | What it does |
| --- | --- | --- |
| `followPath` | Most of a path | Tracks the plan, read a little ahead |
| `turnOnTheSpot` | A path whose two waypoints are at the same place | Spins at the plan's rate. Progress comes from the heading and never goes backward. `crossTrackKp` holds the point. |
| `driveToGoal` | Less than 0.3 m to go and no more than 2° left to turn, on a path that stops | Drives straight at the goal with the [stopping law](/concepts/stopping-law/). Telemetry changes from `TRACKING` to `TERMINAL`. |

`followPath` works in this order.

1. **Read ahead.** The plan is read one latency ahead in plan time. The lead is never less than one loop.

   ```text
   s⁺ = s_plan( t_plan(s) + τ )
   ```

2. **Along the path.** The speed points along the path's direction at `s⁺`. It is the smaller of the plan's speed
   and the stopping law's braking curve.

   ```text
   speed = min( plan speed at s⁺ ,  sqrt(v_end² + 2·a·(d − v·τ)) )
   ```

   `d` is the distance left, `v` the speed last commanded, `a` the braking deceleration, `τ` `latencySeconds`.
3. **Across the path.** The **cross-track error** times `crossTrackKp` pushes back toward the path. With the
   default of 5, a robot 10 cm off is asked for 0.5 m/s sideways.
4. **Heading.** The spin rate is the plan's turn rate at `s⁺`, plus `headingKp` times the heading error, capped
   at the spin limit.

Reading the direction at `s⁺` starts the turn early in a curve, by `v²κτ`.

## When it finishes

| End | Finished when |
| --- | --- |
| A path that stops | Within `positionToleranceMeters` and `headingToleranceRadians`, measured speed below 0.05 m/s, all held for 0.1 s, and the `finishWhen` condition, if any, is true |
| A rolling end, with end speed above zero | The loop nearest to crossing the line through the path's end, within 0.5 m of the end |

After a rolling end, `endCommand()` returns the last velocity commanded. The next follower takes it in
`start(..., handedCommand)`, and its read-ahead grows from zero over the first 0.3 s.

## When something goes wrong

| What | What the follower does |
| --- | --- |
| A shove: the closest point in the search window is more than 0.5 m from the robot | Searches the whole path too, uses that answer if it is at least 5 cm nearer, then steers back |
| A NaN in the measured pose | Does not throw. Asks the limiter for zero velocity and skips progress, events and the finish check for that loop. |

:::caution
The follower has no slip detection. On a floor with less grip than the robot file says, it follows the same plan
and slides. Fix the robot file. See [Traction](/concepts/traction/).
:::

## The numbers

[`FollowerConfig`](/reference/follow/followerconfig/) holds the eight settings a team may change. These are the
library's defaults, not tuned values for any robot.

| Setting | Default | What it does |
| --- | --- | --- |
| `latencySeconds` | 0.05 s | How far ahead the plan is read, and the reaction time in the stopping law. Measure it on the robot. |
| `crossTrackKp` | 5 m/s per meter | Sideways speed per meter off the path. |
| `headingKp` | 5 rad/s per radian | Spin rate per radian of heading error. |
| `brakeMetersPerSecondSquared` | NaN | Braking deceleration. NaN means the robot's traction limit. |
| `easeInPerSecond` | 12 m/s per meter | The slope of the ease-in line at the finish. |
| `headingEaseInPerSecond` | 5 rad/s per radian | The same for heading. |
| `positionToleranceMeters` | 0.02 m | Finished: this close to the goal. |
| `headingToleranceRadians` | 1° in radians | Finished: this well turned. |

The spin limits come from the robot file, or are 540°/s and 720°/s² when the file leaves them out.

These constants inside `PathFollower` are not public and cannot be changed from robot code.

| Constant | Value | Meaning |
| --- | --- | --- |
| `NOMINAL_LOOP_SECONDS` | 0.02 s | The loop time assumed when two steps share a timestamp, and the smallest read-ahead. |
| `WINDOW_METERS` | 0.5 m | The search window for progress, and the shove threshold. |
| `TERMINAL_RADIUS_METERS` | 0.3 m | `driveToGoal` takes over this far from a stopping end. |
| `TERMINAL_TURN_RADIANS` | 2° | It waits until the plan has no more than this left to turn. |
| `STOP_DEADBAND_METERS` | 0.003 m | The finish asks for no speed this close to the goal. |
| `HEADING_DEADBAND_RADIANS` | 0.3° | The finish asks for no spin this close to the goal heading. |
| `SETTLED_METERS_PER_SECOND` | 0.05 m/s | Finished only when measured slower than this. |
| `DEBOUNCE_SECONDS` | 0.1 s | The finish conditions must hold this long. |
| `ROLLING_LEAD_SECONDS` | 0.3 s | After a rolling start the read-ahead grows over this time. |
| `MAX_PROGRESS_RATE` | 8 m/s | Progress faster than this is treated as a jump, not motion, when timing events. |
| `CUSP_EDGE_METERS` | 0.001 m | On a path that doubles back, progress stays this far from the turning point. |
| `GOAL_MOVE_METERS`, `GOAL_MOVE_RADIANS` | 0.02 m, 2° | A bound goal that moves this far re-plans the rest of the path. |
| `MIN_TAIL_METERS` | 0.15 m | Within 0.3 m plus this of the goal, no re-plan: the finish handles it. |
| `GOAL_JUMP_METERS`, `GOAL_JUMP_RADIANS` | 0.25 m, 20° | An averaged estimate this far off is a new goal, not noise. |
| `GOAL_JUMPS_TO_RESTART` | 3 | That many in a row are needed before the average starts again. |

In simulation, growing the read-ahead over 0.3 s cut the wheel slip on a three-path chain from 600 ms to 330 ms
with the same total time.

## What it does not do

- **It does not avoid obstacles.**
- **It does not detect wheel slip** or change its limits during a run.
- **It does not re-plan after a shove.** It steers back. [On-the-fly paths](/concepts/on-the-fly/) do re-plan.
- **It has not run on a real robot.** The numbers here come from the simulator.
