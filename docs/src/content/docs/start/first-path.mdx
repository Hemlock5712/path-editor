This page takes one path from the editor to a moving robot. Run it in the simulator first.

:::note

:::

## Draw and save

<Steps>

1. Open [paths.frc5712.com](https://paths.frc5712.com) and open the robot project's root folder.

2. Pick the **Draw** tool and click two or three points on the blue half of the field. Each click is a
   **waypoint**, a point the path passes through.

3. Rename the path to `FirstPath`.

4. Fill in the robot on the **Settings** page: at least the mass, the bumper size and the distance from the
   center to a wheel.

5. Save. You should see these files appear in the robot project:

   ```text
   src/main/deploy/paths/FirstPath.path.json
   src/main/deploy/paths/robot.json
   src/main/java/frc/robot/PathEditorNames.java
   ```

</Steps>

## Load the library

Do this once, where the drivetrain is built, so it runs in robot init.

```java title="DriveMechanism.java"
import frc.team5712.path.core.FieldFrame;
import frc.team5712.path.follow.FollowerConfig;
import frc.team5712.path.wpilib.PathLibrary;
import frc.team5712.path.wpilib.Pathfinding;

// Reads deploy/paths and plans every path. A bad file stops the robot here, with a message naming the file.
public final PathLibrary paths = PathLibrary.loadAll();

// The factory for every driving command. otf is short for "on the fly".
public final Pathfinding otf = new Pathfinding(
    paths,
    FollowerConfig.defaults(paths.robot()),    // the follower's default settings for this robot
    () -> getPose(),                           // where the robot is
    () -> getFieldVelocity(),                  // how fast, field-relative
    velocity -> driveFieldVelocity(velocity),  // how to drive
    FieldFrame.RED_HALF_TURN);                 // the flip on red. A mirrored field uses RED_MIRROR.
```

:::caution
On WPILib alpha-7 each of the three lambdas goes through the frame conversion. See
[The field frame](/start/drivetrain/#the-field-frame).
:::

## Make the command

```java
import static frc.robot.PathEditorNames.*;

// Requires the drivetrain. The follower is built now, so nothing is planned when the command starts.
Command firstPath = otf.follow(drive, Paths.FIRST_PATH);
```

## Run it in an autonomous

```java title="FirstPathAuto.java"
@Autonomous(name = "First Path")
public class FirstPathAuto extends PeriodicOpMode {
  private final Command routine;

  public FirstPathAuto(Robot robot) {
    routine = robot.drive.otf.follow(robot.drive, Paths.FIRST_PATH);
  }

  @Override
  public void start() {
    Scheduler.getDefault().schedule(routine);   // when autonomous starts
  }

  @Override
  public void end() {
    Scheduler.getDefault().cancel(routine);     // when autonomous ends
  }
}
```

## Try it

<Steps>

1. Start the simulator and set the robot's pose to the start of the path.

2. Select **First Path** and enable autonomous.

3. Watch the robot. You should see it leave along the path, slow for the turns, and stop on the last waypoint.

4. Open AdvantageScope, or the editor's **Telemetry** page, and look under `/Telemetry/Path/FirstPath/`.

   | Entry | You should see |
   | --- | --- |
   | `Phase` | `TRACKING` along the path, `TERMINAL` in the last 30 cm, then `FINISHED` |
   | `Progress` | Meters along the path, rising to the path's length |
   | `CrossTrack` | Meters off the path, staying within a few centimeters |
   | `Reference` | A pose that runs along the path just ahead of the robot |

</Steps>

The command finishes within 2 cm and 1° of the end, slower than 5 cm/s, held for a tenth of a second. Then it
sends a zero velocity.

## Fix a first run

| What happens | Likely cause |
| --- | --- |
| The robot code stops at boot with `path ...FirstPath.path.json: ...` | The file is damaged. Save it again from the editor. |
| It stops at boot with `PathEditorNames doesn't match deploy/paths` | The names class and the deployed files are from different saves. Save, build and deploy again. |
| The robot drives away from the path | The frame conversion is on the pose but not on the velocities, or the other way round. |
| The robot follows the path mirrored | The pose is in the old corner frame and nothing is converted. |
| It runs on blue but drives the wrong way on red | The drive method applies the driver's perspective on top of the library's field velocity. |

[Troubleshooting](/guides/troubleshooting/) has the full list.
