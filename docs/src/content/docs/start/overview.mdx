Myelin gets a swerve robot from one place on the field to another. You draw paths in the **editor**, and the
**library** drives them on the robot. These pages document the library.

## The three parts

| Part | What it is | Where it lives |
| --- | --- | --- |
| The editor | A web app. You draw paths, set the robot's numbers and mark the field's obstacles. | [paths.frc5712.com](https://paths.frc5712.com) |
| The files | What the editor saves: one file per path, plus the robot, the field and a class of names. | `src/main/deploy/paths/` in the robot project |
| The library | Java, on the robot. It reads the files at boot and gives robot code commands that drive. | `vendordeps/Myelin.json` |

The files are the only connection between the editor and the robot. See [Project files](/start/project-files/).

## What the library does

1. **It plans.** At boot, every path file becomes a curve, a heading and a top speed for every point. Starting a
   path later does no planning.
2. **It follows.** Every loop, the follower finds the robot on the path and outputs a velocity for the drivetrain.
3. **It plans on the field.** With no drawn path, the pathfinder finds a route round the obstacles and the same
   follower drives it.

It also has a limiter for driving by hand, a goal that follows an AprilTag, a **rail** that holds the robot to a
line, and an intake assist.

## Who does what

The library moves the robot. Robot code keeps the hardware, the cameras and the driver.

| The library | Your robot code |
| --- | --- |
| Builds and follows paths | Owns the swerve drivetrain and its motors |
| Decides how hard the robot may accelerate | Reports the robot's pose and velocity |
| Plans round obstacles | Takes a velocity and drives at it |
| Filters a tag or game piece once it has been seen | Reads the cameras and turns a detection into a position |
| Fires events by name | Decides what command each event runs |

[What your drivetrain provides](/start/drivetrain/) lists what the library asks for.

## The five packages

Everything is under `frc.team5712.path`. Robot code imports almost entirely from the first row.

| Package | What is in it | Reference |
| --- | --- | --- |
| `wpilib` | The commands and classes robot code calls: `PathLibrary`, `Pathfinding`, `FollowPathCommand`, `DriveLimiter`, `TagGoal`, `RailDrive` | [wpilib](/reference/wpilib/pathlibrary/) |
| `follow` | The follower and the laws inside it: `PathFollower`, `FollowerConfig`, `StoppingLaw`, `OutputLimiter` | [follow](/reference/follow/pathfollower/) |
| `plan` | The pathfinder: `Pathfinder`, `OnTheFly`, `FieldMap` | [plan](/reference/plan/pathfinder/) |
| `core` | The path maths, with no dependencies: the curve, the heading, the speed plan, the file readers | [core](/reference/core/path/) |
| `sim` | A small simulated drivetrain for trying a follower without a robot | [sim](/reference/sim/followersim/) |

## Where it stands

The current version is **2027.0.0-alpha-2**, built against WPILib 2027 alpha-7 and Commands v3. Its tests pass,
and the team's robot project drives it in the CTRE simulator.

:::caution[Not yet on a real robot]
The library has not run on a real robot. Treat every default as a starting point, and read
[Tuning](/guides/tuning/) before the first run on carpet.
:::

:::caution[The field origin]
The library's origin is the center of the field, with +X toward the blue alliance wall. WPILib 2027 alpha-7 and
alpha-8 still report poses from the blue corner, so robot code must convert every pose and velocity. See
[What your drivetrain provides](/start/drivetrain/#the-field-frame).
:::
